A Simple Computer

How a processor fetches, decodes, and executes instructions — from the architecture and instruction set to data movement, arithmetic, memory writes, and jumps.

1. Learning goals and the big idea

A computer program is a sequence of instructions stored in memory. The processor repeatedly retrieves an instruction, interprets what it means, and performs the required operation.

Understand the machine

Identify the CPU, memory, input/output, buses, and key registers.

Read instructions

Recognize opcodes, operands, instruction categories, and addressing modes.

Trace execution

Follow the PC, IR, registers, ALU, and memory through each instruction.

Central idea: The CPU does not “understand” a high-level statement such as C = A + B. A compiler or assembler translates a program into machine instructions that the processor's instruction set defines.

2. Architecture of a simple computer

The architecture describes the major components and how they cooperate to execute a program.

Conceptual diagram: actual computer designs differ in their internal organization and bus implementation.

CPU: the processor

  • Control Unit (CU): interprets instructions and coordinates operations.
  • Arithmetic Logic Unit (ALU): performs arithmetic and logical operations.
  • Registers: very small, fast storage locations inside the CPU.

Main memory

Stores the instructions and data currently needed by the program. Each address identifies a location in memory.

In a classic stored-program model, instructions and data share the same memory address space.

3. Instruction sets: the language of the CPU

An instruction set is the collection of operations a processor is designed to recognize. The programmer-visible specification is commonly called the Instruction Set Architecture (ISA).

3.1 Opcode and operands

ADD R2, R0, R1
│   │   │   └── second source operand
│   │   └────── first source operand
│   └────────── destination operand
└────────────── opcode (operation)

The opcode says what to do; the operands say which data or locations are involved.

Instruction syntax varies by processor and assembler. In this teaching notation, the destination register is written first.

4. The instruction cycle: Fetch → Decode → Execute

The CPU repeats this cycle to process a program. The exact internal micro-operations vary by processor, but the basic idea is widely applicable.

FETCH
→
DECODE
→
EXECUTE
↻
Stage 1

Fetch

  1. PC contains the next instruction address.
  2. CPU sends that address to memory.
  3. Memory returns the instruction.
  4. Instruction is placed in IR.
  5. PC advances to the next sequential instruction (unless control flow changes it).
Stage 2

Decode

  1. Control Unit examines the opcode.
  2. It identifies source and destination operands.
  3. It determines whether registers, ALU, memory, or flags are needed.
  4. It prepares the required control signals.
Stage 3

Execute

  1. ALU performs arithmetic/logic, or data is transferred.
  2. Result is written to a register or memory.
  3. Status flags may be updated.
  4. CPU proceeds to the next instruction.

4.1 A closer look at a memory read

  1. PC → address path: the address of the next instruction is selected.
  2. Memory Read: the control unit requests a memory read.
  3. Memory → IR: the fetched instruction is transferred into the instruction register.
  4. PC update: the PC is advanced to the next instruction address in this simple sequential model.

In a real processor, fetching may involve caches, pipelines, instruction prefetch, and several internal stages.

5. Worked examples: follow every instruction

The examples use the teaching instruction set defined above. The address numbers identify instruction locations; the data addresses 40, 41, and 42 hold program data.

Example 1 — LOAD: copy a value from memory to a register

Memory[40] = 161

LOAD R0, [40]
StageWhat happensResult
FetchRead the instruction at the PC and place it in IR.IR = LOAD R0, [40]
DecodeIdentify LOAD, destination R0, source address 40.Read Memory[40]
ExecuteTransfer the value at address 40 into R0.R0 = 161
Remember: LOAD copies data into a register. It does not erase the original value in memory.

Example 2 — Addition: 161 + 254

Initial data: Memory[40] = 161, Memory[41] = 254.

00: LOAD  R0, [40]
01: LOAD  R1, [41]
02: ADD   R2, R0, R1
03: STORE [42], R2
04: HALT

Instruction-by-instruction trace

PCInstructionOperationState after execution
00LOAD R0, [40]Read Memory[40]R0 = 161
01LOAD R1, [41]Read Memory[41]R1 = 254
02ADD R2, R0, R1ALU: 161 + 254R2 = 415
03STORE [42], R2Write R2 to Memory[42]Memory[42] = 415
04HALTStop the programExecution halted
Follow the data: Memory → R0 and R1 → ALU → R2 → Memory[42].

Example 3 — SUB and bitwise logic

Suppose R0 = 25 and R1 = 10. In 8-bit binary:

25 = 00011001
10 = 00001010

SUB: 25 - 10 = 15
AND: 00001000 = 8
 OR: 00011011 = 27

The ALU is not only an arithmetic calculator. It also performs Boolean operations on bit patterns.

Example 4 — JMP: change the normal instruction sequence

00: MOVI R0, #7
01: JMP  04
02: MOVI R1, #99
03: STORE [41], R1
04: HALT

After the jump at address 01, the PC is set to 04. Instructions at addresses 02 and 03 are skipped. Therefore R1 is not loaded with 99, and address 41 is not written by this program.

Example 5 — Conditional jump

00: MOVI R0, #5
01: MOVI R1, #5
02: CMP  R0, R1
03: JZ   05
04: MOVI R2, #0
05: HALT
  1. CMP R0, R1 compares the two register values.
  2. Because both values are 5, the teaching machine sets its zero/equal flag.
  3. JZ 05 takes the branch to address 05.
  4. Address 04 is skipped; R2 is not changed by that instruction.

Real ISAs differ in how comparison results and condition flags are represented.

8. Summary: what students should remember

  1. A computer executes instructions stored in memory.
  2. The CPU contains a Control Unit, ALU, and registers.
  3. The instruction set defines the operations available to software.
  4. An instruction includes an opcode and operand information.
  5. The PC identifies the next instruction; the IR holds the current instruction.
  6. LOAD moves data from memory to a register; STORE moves data from a register to memory.
  7. The ALU performs arithmetic and logical operations.
  8. Jumps change the normal sequence by changing the PC.
  9. The simplified instruction cycle is Fetch → Decode → Execute.
Instructor note: connection to real processors

This module intentionally uses a small, transparent teaching ISA and a one-instruction-per-address model. Actual processors have architecture-specific instruction encodings, registers, addressing rules, status flags, and execution details. Modern CPUs may overlap instruction stages through pipelining and use caches, branch prediction, and out-of-order execution. Introduce those topics only after students can confidently trace the simple model.

Suggested follow-up topics

Binary instruction encoding, machine-code translation, Boolean logic in the ALU, signed integer arithmetic, memory hierarchy, interrupts, pipelining, and the relationship between assembly language and high-level programming languages.
